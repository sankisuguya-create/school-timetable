# 起動・画面切替・初回案内のレビュー（2026-09-14）

基点: origin/main `4a2ac554328dfc6eb38a74f41014caba6372810c`（PR9マージ済み）。
本変更はmainへのマージ、本番GASへのデプロイ、データ移行を行わない。

## 再現できた原因

HTMLの出力操作は `data-act="outweek"` へ変更されていたが、
`gate.js` の `showGate()` と `openView()` は削除済みの `data-act="print"` を検索し、
nullの `.hidden` に代入していた。`start()` は `showGate()` を先に呼ぶため、
初期グリッド・ヘッダー描画、`Backend.boot()`、案内の予約まで到達しない。
週切替は直接描画を呼ぶため一部表示が復旧するが、起動通信が始まっていない。
症状とコードの両方に一致する。案内やキャッシュが主因だったとは確認できない。

`BASELINE_REF=origin/main node tools/startupcheck.cjs` はこのnull代入で失敗し、
修正後は同じ起動検査を通る。キャッシュ形状の修正だけでは直らない。

## 変更

- 出力ボタンに共通の `data-plan-output` を付け、表示切替を1関数に集約。
- 週切替・画面切替の読み込みと描画を共通化。待機を開始した処理だけが待機数を減らす。
- 正常な編成データは正規化時に同じ参照を返し、編集中配列と空学年・空専科を維持。
- 自動画面移動を伴う旧ツアーを短い標準dialogに置換。初回自動表示、閉じる、
  左メニュー「使い方」から再表示。案内失敗が起動を停止しない。
- 右の授業チップは通常表示、週案内のチップ装飾は既定オフを維持。
  右メニューから変更できることを実DOMで確認。既存の選択設定は上書きしない。
- HTMLとJSの固定ID参照、起動、出力切替、設定参照、同期・非同期の待機を回帰検査。
- 版番号を1.18.0に更新し生成HTMLも同期。

## 検証

`npm run check:core` 成功（生成物一致、起動回帰、実HTML+全JSのDOM検査、
既存GAS store/gate/api検査）。DOM検査はローカル、GAS成功モック、通信失敗モック、
案内既読、案内表示失敗の5条件。週を切り替えず入口・週案・授業チップが描かれ、
装飾切替と案内再表示が動く。全src/jsの構文検査と `git diff --check` も成功。

Chromium取得がタイムアウトし、`node tools/check.mjs` は実行ファイル不在で起動できない。
したがってブラウザの実レイアウト、ネイティブdialogのEscape操作、印刷、画像出力、
実GAS接続を確認済みとはしない。追加したブラウザ案内テストは未実行。
実デプロイ後に新規端末・既存端末で初回表示、案内、保存・再読込を受入確認する必要がある。

## 今回変更しない注意点

全体構成・ブランチ差分・画面/通信の接続を確認したが、全機能の無欠陥は保証しない。
GASの保存形式・認可・移行処理は今回変更していない。
出力設定には別の不整合がある：PNGは画面DOMの複製なので「画面だけ」の装飾も写り、
Sheet出力は値の表で装飾設定を受け取らないのに、設定の文言はSheetも対象としている。
この出力仕様の整理と実出力検証は、起動修正に混ぜず別途対応する。
