# 保存・提出・出力の状態（1.19.0）

## 画面

- 保存が成功したとき、作業面の背景をわずかに硬質な灰色へ変える。
  週案の編集が入ると元へ戻す。送信中・失敗・未解決の競合がある間は保存済みの背景にしない。
- 提出ボタンは、提出成功後にオレンジ色になる。
- 提出後に週案を編集すると「未提出の変更あり！」を表示する。
  保存だけでは消えず、再提出で消える。学年・全校・専科から対象学級への変更も含む。
- 学年の作業面は青空と雲、学校全体は暗い星空。静的CSSのみを使い、外部画像・動画・アニメーションは使わない。
  紙面は白のままで、背景は印刷へ出さない。学級画面の入力範囲を学年・全校に切り替えた場合も背景を変える。

## たんぽぽの印

| 印 | 意味 |
|---|---|
| 未 | 未提出、または提出後に変更が入り再提出が必要 |
| 済 | 初回提出済み、または現在の提出をこの出力先へ反映済み |
| 変（紫） | この出力先に前の提出の出力記録があり、再提出分がまだ未出力 |

初回提出は「済」。一度出力したあと、編集→保存→再提出で「変」、再出力成功で「済」に戻る。
出力記録はファイルID別・年度別・週別・学級別なので、別の出力先へ出しても現在の出力先の「変」は消えない。
出力失敗では反映済みにしない。再提出前の変更や、表示後に変わった提出版を検出したら出力を止める。
他端末の変更は画面を開き直したとき・定期読込時に反映される。リアルタイム配信ではない。

## 保存関連4件の修正

1. 送信中の再保存は同じ処理の完了を待つ。未送信・送信中・競合保留を未保存件数に含める。
2. 読込結果で送信中のコマを置換しない。読込開始後に編集または保存応答があった場合も古い結果を適用しない。
3. 競合した自分の入力は、解決まで端末に保持し、再起動時に復元する。
   自分の入力を再適用する場合は、送り待ちへ移してから競合の控えを外す。
4. 提出・たんぽぽ出力は保存成功かつ競合解決後に進む。失敗時は出力しない。

## 導入

GASの `Sheets.gs`、`Store.gs`、生成済み `plan.html` を同じ版で反映し、デプロイを更新する。
「たんぽぽ状態」シートは必要時に自動追加する。既存の「たんぽぽ提出」シートの列やデータは変更しない。
提出日時は再提出を識別できる精度のISO日時へ更新する。画面・サーバを更新後、利用中のタブは読み込み直す。

過去の出力には提出版の記録がないため、更新後に一度出力するまでは「変」と判定しない。
「教師わりあて」の転記と、再出力時の旧シート退避は引き続き有効。

## 検査

- `npm run check:core`: 起動・DOM・保存応答順・競合復元・GAS保存/権限/API。
- `npm run check:state`: 実ブラウザで保存背景、提出/再提出、紫の「変」、範囲背景、保存失敗時の停止。
- `npm run check`: 上記と既存の画面・GAS接続モック検査。
- 学校で別の2アカウントを使い、編集→保存→提出→出力→編集→保存→再提出→再出力を確認する。
  本番GAS・40人同時操作・実プリンタでの受入試験は別途必要。

今回の保存状態は週案セル・週メモを対象とする。基本時間割や学級編成の管理操作の版競合、
PNG/Sheetの装飾仕様の不整合など、前回レビューの別課題を解決したという意味ではない。
